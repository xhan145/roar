# ROAR $19/$29/$49 Pricing + Stripe-Ready Static Site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move paid pricing to Core free / Pro $19 / Developer $29 / Supporter $49, centralise it in one definition, rebuild the public pricing page, and make checkout Stripe-ready via Payment Links — with no server.

**Architecture:** `commercial_config.PRICING` becomes the single source of truth; the existing `*_PRICE_USD` constants stay as values derived from it so `upgrade_prompts.py` keeps working. The static `site/index.html` mirrors those numbers and gains four cards plus a success page; a `fulfillment.py` boundary documents (and explicitly refuses) automated licence signing.

**Tech Stack:** Python 3.14 (flat modules, pytest), static HTML/CSS/JS in `site/` deployed by `.github/workflows/pages.yml`.

## Global Constraints

- Prices: **core 0, pro 19, developer 29, supporter 49** (USD, one-time). Labels: `Free`, `$19 once`, `$29 once`, `$49 once`.
- Edition IDs stay `core` / `pro` / `developer` / `supporter`. **Prices are never entitlement identifiers.**
- Display names: **ROAR Core / ROAR Pro / ROAR Developer / ROAR Supporter**. Customer-facing copy says "Developer", not "Developer Pack".
- Supporter has **no exclusive features** — same access as Developer.
- Never break: Core is free and useful; dictation needs no licence; no account, no cloud transcription, no telemetry, no subscription; privacy controls, history deletion and audio deletion are never paid-only; licence validation is offline; licensing code never reads transcript/audio/history/clipboard/vocabulary/insight data.
- **No secrets in the repo:** no `sk_`/`whsec_` Stripe keys, no private signing key. Payment Links (public `https://buy.stripe.com/...` URLs) are allowed.
- Server-side checkout/webhook is **out of scope** — GitHub Pages cannot execute it; document only.
- Run tests with `venv/Scripts/python.exe -m pytest <path> -v`. Full suite must stay green (currently 654 passed / 3 skipped).
- Commit after every task.

```python
# fulfillment.py
"""Boundary for future automated licence delivery — deliberately NOT implemented.

ROAR sells through Stripe Payment Links on a STATIC site, so there is no server
to receive a webhook and no secure home for the Ed25519 signing key (it lives
only in the owner's `~/.roar-signing/`). Signing here would mean shipping that
key somewhere it does not belong, so this module refuses instead of pretending.

Today's real path is manual and honest:
    1. Stripe emails you that a payment completed.
    2. You run `python scripts/issue_license.py --edition <id> --name … --email …`.
    3. You send the resulting .json to the buyer.

A production implementation MUST:
    1. Confirm the payment really completed, by asking Stripe — never trust the
       browser, a redirect, or a query parameter.
    2. Validate the purchased edition against PAID_EDITIONS.
    3. Be idempotent on the Stripe Checkout Session id (one licence per sale).
    4. Sign with the existing offline licence format, on a secure server only.
    5. Deliver over a channel the buyer controls.
    6. Store no voice, transcript, or application-usage data.
    7. Follow a written refund/revocation policy.
"""
from dataclasses import dataclass

import commercial_config as cc


class FulfillmentUnavailable(RuntimeError):
    """Automated delivery is not configured; use the manual path."""


@dataclass(frozen=True)
class LicenseDeliveryResult:
    delivered: bool
    edition: str
    stripe_session_id: str
    reason: str


def issue_license(edition, stripe_session_id, customer_email=None,
                  major_version=cc.CURRENT_MAJOR_VERSION):
    """Validate a fulfilment request, then refuse to sign.

    Raises ValueError for a bad request and FulfillmentUnavailable for a good
    one — a good request failing loudly is the point.
    """
    if edition not in cc.PAID_EDITIONS:
        raise ValueError(f"{edition!r} is not a purchasable edition")
    if not isinstance(stripe_session_id, str) or not stripe_session_id.strip():
        raise ValueError("a Stripe Checkout Session id is required")
    if int(major_version) != cc.CURRENT_MAJOR_VERSION:
        raise ValueError(f"unsupported major version {major_version!r}")
    raise FulfillmentUnavailable(
        "Automated licence delivery is not available: this site is static and "
        "the signing key is intentionally offline. Issue the licence manually "
        "with scripts/issue_license.py, then send it to the buyer.")
```

# Selling ROAR with Stripe Payment Links

ROAR's site is **static** (GitHub Pages), so there is no server to create
Checkout Sessions or receive webhooks. Payment Links are the right fit: Stripe
hosts the payment page, and the amount is fixed on Stripe's side — a visitor
cannot tamper with the price even though the link is public.

## 1. Create three one-time prices

In the Stripe Dashboard, create three products, each with a **one-time** price
(never recurring):

| Product          | Price |
|------------------|------:|
| ROAR Pro         |   $19 |
| ROAR Developer   |   $29 |
| ROAR Supporter   |   $49 |

## 2. Create a Payment Link per product

For each product create a Payment Link. Under "After payment", set a redirect to:

    https://xhan145.github.io/roar/purchase/success.html

## 3. Put the links in the site

Paste each link into the `purchase` block of `site/index.html`:

```js
purchase: {
  pro: "https://buy.stripe.com/…",
  developer: "https://buy.stripe.com/…",
  supporter: "https://buy.stripe.com/…",
},
```

Commit and push; GitHub Pages redeploys. Payment Links are **public URLs and are
safe to commit**. A Stripe *secret key* or *webhook secret* is never safe to
commit and is not needed for this setup.

## 4. Fulfil the licence

> **Stripe payment completion must not automatically imply that a license was
> delivered.** Delivery only counts once you have issued and sent the licence.

Today this is manual and deliberate — the Ed25519 signing key lives only on the
owner's machine (`~/.roar-signing/`), never on a server:

1. Stripe emails you that a payment succeeded.
2. Confirm it in the Stripe Dashboard (never trust a redirect or a URL parameter).
3. Run:

   ```bash
   export ROAR_LICENSE_PRIVATE_KEY_FILE=~/.roar-signing/roar_license_private_key.pem
   python scripts/issue_license.py --edition pro --name "Buyer Name" --email buyer@example.com
   ```

4. Email the resulting `.json` to the buyer. They import it in
   Settings → License.
5. Record the Stripe payment id you fulfilled, so a duplicate email cannot
   produce a second licence.

## 5. Test before charging anyone

Use Stripe **test mode** first: complete a purchase, cancel one, and repeat a
purchase. Keep test and live links separate — never paste a test link into the
live site.

## Refunds

Refund in Stripe. A refunded licence stays technically valid (validation is
offline), so refund policy is a trust matter — record refunds alongside the
issued-licence log.

## If you ever move to a real backend

See `docs/WEBSITE_IMPLEMENTATION.md` for the server-side contract
(`POST /api/checkout`, webhook signature verification, idempotency).
```

```markdown
# Website implementation notes

## Today

`site/` is plain static HTML deployed to GitHub Pages by
`.github/workflows/pages.yml` (`path: site`). There is **no server, no
serverless function, and no build step**. Checkout therefore uses Stripe
Payment Links (see `docs/STRIPE_SETUP.md`), which need no backend.

## If the site moves to a host with functions (Vercel, Netlify, Cloudflare)

Only then do the server-side pieces become possible. The contract:

### POST /api/checkout

- Accept POST only; reject other verbs with 405.
- Body: `{"edition": "pro" | "developer" | "supporter"}` — the browser sends an
  **edition id and nothing else**. Never accept a price or a Stripe Price ID
  from the client.
- Reject unknown editions and `core`.
- Map the edition to a Price ID from server-side environment variables:
  `STRIPE_PRICE_PRO`, `STRIPE_PRICE_DEVELOPER`, `STRIPE_PRICE_SUPPORTER`.
- Create a session with `mode: "payment"` (never a recurring mode), quantity 1,
  success/cancel URLs built from `PUBLIC_SITE_URL`, and metadata
  `{product: "roar", edition, license_major: "1"}`.
- Send no transcripts, machine ids, history, or app configuration to Stripe.
- Return a generic error message; log no secrets.

### POST /api/stripe/webhook

- Verify the Stripe signature against `STRIPE_WEBHOOK_SECRET` using the **raw**
  request body; reject invalid signatures.
- Handle `checkout.session.completed` (and optionally `charge.refunded`).
- Be idempotent on the Checkout Session id; store processed event ids.
- Re-validate the edition from metadata — never trust it blindly.
- Only then call the fulfilment boundary (`fulfillment.issue_license`).

### Environment (server-side only)

```env
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
STRIPE_PRICE_PRO=
STRIPE_PRICE_DEVELOPER=
STRIPE_PRICE_SUPPORTER=
PUBLIC_SITE_URL=https://example.com
```

`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` and the licence **signing key**
must never reach the browser, the desktop app, or this repository.
```
